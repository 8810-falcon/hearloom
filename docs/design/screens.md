# Hearloom 画面設計

**最終更新: 2026-02-04**

## 概要

本ドキュメントはHearloom MVPの画面設計を定義する。技術スタックはReact + TypeScript + Vite（Web UI）で、iOS/AndroidのネイティブシェルがWebViewでホスティングする。

---

## 画面一覧と遷移図

### 画面一覧

| 画面名 | 役割 | 起動経路 |
|--------|------|----------|
| 記録画面 | 新規記録の入力 | 音楽アプリの共有メニューから起動 |
| 一覧画面 | 過去の記録を閲覧（ホーム画面） | アプリアイコンタップで起動 |
| 編集画面 | 既存記録の編集 | 一覧画面から記録をタップ |

## 記録画面（新規登録）

共有メニューから起動し、曲の共有URLが自動反映された状態で開く画面。

### ワイヤーフレーム

```
┌────────────────────────────────────────┐
│ ←  記録する                             │  ← ヘッダー（キャンセル）
├────────────────────────────────────────┤
│                                        │
│  ┌────────────────────────────────┐    │
│  │  [曲情報カード]                  │    │
│  │  ─────────────────────────────  │    │
│  │  URL: spotify.link/xxx...       │    │  ← 共有URLを表示
│  │                                 │    │
│  └────────────────────────────────┘    │
│                                        │
│  今の気分は？ *必須                     │
│                                        │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐  │
│  │ 高揚  │ │ 穏やか │ │ 切ない │ │ 集中  │  │
│  │  ^_^  │ │  -_-  │ │  ;_;  │ │  o_o  │  │
│  └──────┘ └──────┘ └──────┘ └──────┘  │
│  ┌──────┐ ┌──────┐                     │
│  │ 懐かし │ │ その他 │                    │
│  │  ◡_◡ │ │  ...  │                    │
│  └──────┘ └──────┘                     │
│                                        │
│  どんな状況？ *必須                     │
│  ┌────────────────────────────────┐    │
│  │ 例: 朝の通勤電車で               │    │  ← テキスト入力（1行）
│  └────────────────────────────────┘    │
│                                        │
│  ┌────────────────────────────────┐    │
│  │           保存する               │    │  ← プライマリボタン
│  └────────────────────────────────┘    │
│                                        │
└────────────────────────────────────────┘
```

### 構成要素

| 要素 | 詳細 |
|------|------|
| ヘッダー | 「← 記録する」（左矢印タップでキャンセル、音楽アプリに戻る） |
| 曲情報カード | 共有URLを表示（曲名取得はMVP後の拡張機能） |
| 気分選択 | 6つのボタン（単一選択、必須） |
| 状況入力 | 1行テキスト入力（プレースホルダー: 「例: 朝の通勤電車で」、必須） |
| 保存ボタン | プライマリカラー、気分と状況が入力されたら活性化 |

### インタラクション仕様

- **気分ボタン**: タップで選択状態に変化（選択中は枠線+背景色変化）
- **状況入力**: フォーカス時にキーボード表示、改行不可（Enter無効）
- **保存ボタン**: 必須項目が未入力の場合は非活性（グレーアウト）
- **保存成功時**: 音楽アプリに戻る（WebViewを閉じる）
- **キャンセル時**: 入力内容があれば確認ダイアログ、なければそのまま戻る

```
│  │  ◡_◡ │ │  ...  │                    │
│  └──────┘ └──────┘                     │
│                                        │

│  ┌────────────────────────────────┐    │
│  │ 仕事前のテンション上げに          │    │  ← 既存の値が入力済み
│  └────────────────────────────────┘    │
│                                        │
│  ┌────────────────────────────────┐    │
│  │           保存する               │    │
│  └────────────────────────────────┘    │
│                                        │
└────────────────────────────────────────┘
```

### 構成要素

| 要素 | 詳細 |
|------|------|
| ヘッダー | 「← 編集」（左矢印で一覧に戻る）+ 右上に「削除」ボタン |
| 記録日時 | 表示のみ（編集不可） |
| 曲情報カード | URL表示のみ（編集不可） |
| 気分選択 | 現在の選択がハイライト状態、変更可能 |
| 状況入力 | 既存の値が入力された状態、変更可能 |
| 保存ボタン | 変更があった場合のみ活性化 |

### インタラクション仕様

- **「← 」タップ**: 変更がなければそのまま一覧に戻る、変更があれば確認ダイアログ
- **「削除」タップ**: 確認ダイアログ「この記録を削除しますか？」→ 削除 → 一覧に戻る
- **保存タップ**: 保存 → 一覧に戻る

## 気分選択の設計

### 選択肢一覧

| ID | 気分名 | 顔文字 | 選択時の背景色 | 選定理由 |
|----|--------|--------|---------------|----------|
| excited | 高揚 | ^_^ | #FFA726 (オレンジ) | テンション上げ、運動、プレゼン前 |
| calm | 穏やか | -_- | #66BB6A (グリーン) | リラックス、移動中、家事中 |
| melancholy | 切ない | ;_; | #42A5F5 (ブルー) | 感情を吐き出したい時、失恋、寂しい夜 |
| focused | 集中 | o_o | #AB47BC (パープル) | 仕事・作業時のBGM |
| nostalgic | 懐かし | v_v | #8D6E63 (ブラウン) | 過去の記憶と結びつく曲 |
| other | その他 | ... | #BDBDBD (グレー) | 上記に当てはまらない場合 |

### 設計根拠

1. **選択肢数（6個）**: 認知負荷の観点で5-7個が最適（ミラーの法則）。2行x3列でバランスよく配置可能。

2. **選択肢の導出元**:
   - ユーザーインタビュー結果「感情タグ付け機能が最も刺さる」
   - ユーザージャーニーの音楽聴取パターン（高揚、没頭、リラックス等）

3. **「その他」の必要性**: エスケープハッチとして、想定外の気分にも対応可能に。

### UIパターン

- **未選択状態**: 透明背景、グレー枠線
- **選択状態**: 各気分の背景色、太枠線
- **タッチフィードバック**: タップ時に軽いスケールアニメーション（0.95倍）

## データモデル

### Record型

```typescript
export type MoodType = 'excited' | 'calm' | 'melancholy' | 'focused' | 'nostalgic' | 'other';

export interface Record {
  id: string;                    // UUID v4
  url: string;                   // 共有URL
  mood: MoodType;                // 気分
  situation: string;             // 状況の一言
  createdAt: string;             // ISO 8601形式（例: 2026-02-04T20:30:00+09:00）
  updatedAt: string;             // ISO 8601形式
}
```

### LocalStorageキー

```
hearloom_records: Record[]  // 全記録の配列をJSON文字列で保存
```

## ネイティブシェルとの責務分離

| 機能 | 担当 | 備考 |
|------|------|------|
| 共有メニュー対応 | ネイティブ | iOS: Share Extension, Android: Intent Filter |
| WebView表示 | ネイティブ | URL渡しでWeb UIを表示 |
| 共有URLの受け渡し | ブリッジAPI | ネイティブ → Web UIにURLを渡す |
| UI表示・入力処理 | Web UI | React実装 |
| LocalStorage操作 | Web UI | ブラウザ標準API |
| アプリ終了・戻る | ネイティブ | WebView閉じる処理 |

### ブリッジAPI仕様（概要）

```typescript
// Web UI側から呼び出し
interface NativeBridge {
  // 共有URLを取得（記録画面起動時）
  getSharedUrl(): Promise<string | null>;

  // アプリを閉じる（保存/キャンセル後）
  closeApp(): void;
}
```

## アクセシビリティ配慮

| 項目 | 対応内容 |
|------|----------|
| フォーカス管理 | Tab順序を論理的に（ヘッダー → 気分選択 → 入力 → ボタン） |
| ARIA属性 | 気分選択: `role="radiogroup"`、各ボタン: `role="radio"` + `aria-checked` |
| コントラスト比 | WCAG AA基準（4.5:1以上）を満たす配色 |
| タッチターゲット | 最小44x44pt（iOS HIG）/ 48x48dp（Material Design） |
| 状態の伝達 | 選択状態は色だけでなく、枠線の太さでも表現 |
| スクリーンリーダー | ボタンにaria-label付与（例: `aria-label="高揚を選択"`) |
