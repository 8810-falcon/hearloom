# Hearloom プロダクトコンセプト

**最終更新: 2026-02-11**

## アプリ名

Hearloom（Hear + Heirloom）

## コンセプト

音楽を記録すると「曲のエピソード」が見れる。記録が蓄積されると、ふとした瞬間に過去の音楽と思い出を届けてくれるアプリ。

## 本質的に届けたい体験

> 「ふとした瞬間に過去聞いていた音楽を、場所や時間帯、期間などに応じてユーザーに投げかけることで、過去の思い出を想起させる」

## 解決する課題

### 旧コンセプトの課題
- 「記録先行」だとユーザーは見返りがないまま記録を続けなければならない
- 自動収集は技術的制約（タイムスタンプ取得不可、バックグラウンド同期不可）で実現困難

### 新コンセプトでの解決
- **即時報酬**: 記録すると「曲のエピソード（裏話・豆知識）」がすぐ見れる
- **能動的記録**: 「この曲を記録したい」という意志がある曲だけを記録
- **蓄積価値**: 記録が溜まると「ふとした通知」で思い出を想起

## コア価値

| 価値 | 詳細 |
|------|------|
| **即時報酬** | 記録するとAIが生成した曲のエピソードがすぐ見れる |
| **思い出の蓄積** | 曲 × 気分 × 時間 × 場所が自動で紐づく |
| **セレンディピティ** | ふとした瞬間に過去の音楽と思い出を届ける通知 |

## 差別化ポイント

| 競合 | 違い |
|------|------|
| Last.fm | データ・数字中心 → Hearloom: **エピソード・感情中心** |
| Spotify Wrapped | 年1回のまとめ → Hearloom: **日常的に記録＆振り返り** |
| 音楽日記アプリ | 記録だけ → Hearloom: **記録すると即エピソードが見れる報酬構造** |
| Genius | 歌詞・解説を見るだけ → Hearloom: **記録と紐づいて思い出になる** |

## ターゲットユーザー

**音楽マニア**
- 音楽を深く楽しみたい人
- 曲の背景やアーティストのストーリーに興味がある人
- 自分の音楽体験を記録・振り返りたい人

## 技術スタック（確定）

| 機能 | iOS | Android |
|------|-----|---------|
| Apple Music再生曲取得 | SystemMusicPlayer.shared | - |
| Spotify再生曲取得 | Spotify SDK (SPTAppRemote) | MediaSessionManager or Spotify SDK |
| エピソード生成 | **Apple Intelligence（オンデバイス）** | **Gemini Nano（オンデバイス）** |

### 対応デバイス・機能差

| プラットフォーム | エピソード機能 | 記録機能 |
|-----------------|---------------|----------|
| iOS（iPhone 15 Pro以降） | ✅ | ✅ |
| iOS（それ以前） | ❌ | ✅ |
| Android（Gemini Nano対応機） | ✅ | ✅ |
| Android（非対応機） | ❌ | ✅ |

※古いデバイスでも記録機能は利用可能（エピソード表示のみ非対応）

### エピソード生成の方針

- **コスト**: 0円（端末内で完結、バックエンド不要）
- **対応範囲**: 有名曲のみ（モデルの学習データに含まれる曲）
- **非対応時UX**: 「エピソードが見つかりませんでした。代わりに一言を残しませんか？」

## 残存リスク

| リスク | 深刻度 | 現状 | 対策 |
|--------|--------|------|------|
| オンデバイスAIの品質 | 高 | 未検証 | プロンプト改善、実機検証 |
| エピソード生成可能な曲の範囲 | 中 | 未検証 | 有名曲でテスト、非対応時は一言メモを促す |
| 対応デバイスの制限 | 中 | 許容済み | 新しいデバイスのみサポート |
| 継続利用率 | 中 | 未検証 | エピソードの魅力向上、通知設計の工夫 |
| Spotify/Appleが同機能を実装 | 低 | 未発生 | 感情・文脈記録で差別化 |
