# Hearloom 機能一覧

**最終更新: 2026-02-04**

## Must have（MVP必須）

- 以下の音楽アプリから、共有メニューを開いた際にHearloomが表示される
  - Apple Music
  - Spotify
  - YouTube
- ユーザーは、共有メニューからHearloomをタップすると、曲の共有用URLが自動でHearloomの記録画面に反映される
- その時の気分を選択（必須）+ そのときの状況を一言 or 一文（必須）で入力
- 保存押下でHearloomの記録として、日時情報とともに記録できる
  - 保存精度: YYYYMMDDHHMM（年月日時分）
  - 表示粒度: 日付 + 時間帯（朝 / 昼 / 夕 / 夜）
- 保存先はWebViewに永続化（disk保存）
- 記録の一覧は日付順（最新順）で表示され、ユーザーは記録を見ることができる
- 記録の新規登録は、MVPとして音楽アプリの共有メニューからの導線のみとする。ただし、記録した内容は一覧からレコード選択→編集画面に遷移することで編集を行うことができる。

## Should have（価値向上）- P1

| 機能 | 詳細 |
|------|------|
| セレンディピティ通知 | 「1年前の今日」など、過去の記録をリマインド |
| 時系列での履歴閲覧強化 | 月別、年別でのフィルタリング・振り返りUI |
| 記録の検索・絞り込み | 気分、曲名、アーティストで検索 |
| アプリ内からの新規記録 | 共有メニュー経由でなく、アプリ内で直接記録 |

## Could have（後回し可能）- P2

| 機能 | 詳細 |
|------|------|
| Spotify連携 | 聴取履歴の自動収集（記録コスト削減） |
| Apple Music連携 | 聴取履歴の自動収集（タイムスタンプなし） |
| AIによる感情推定 | 蓄積データから傾向分析・推定（参考表示） |
| 年次レポート | 1年間の音楽体験をストーリー化 |
| 場所情報との紐付け | オプトイン方式 |

## Won't have（MVPでは除外）

| 機能 | 除外理由 |
|------|----------|
| YouTube連携 | 視聴履歴API無効化（2016年〜）、技術的に実装不可能 |
| 楽曲再生機能 | ライセンス問題、各音楽アプリに委譲 |
| 自動整理ライブラリ | 既存サービスで代用可能、差別化不足 |
| リアルタイム再生監視 | バッテリー消費大、OS制約 |
