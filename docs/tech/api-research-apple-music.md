## 重大な制約事項

### 1. 再生時刻（タイムスタンプ）が取得できない

**影響:**
- コア機能「時間帯×ジャンル×頻度からAIで感情推定」の直接実装が困難
- 「朝の通勤時にchill系」「夜遅くに激しい曲」などのパターン検出が不可能
- 差別化ポイント「記録コストゼロ」の価値が低下

**原因:**
- Apple Music APIの`/v1/me/recent/played/tracks`エンドポイントは再生時刻を返さない
- Apple Developer Forumsで多数のリクエストがあるが、2026年1月時点で未実装

**代替アプローチ（トレードオフあり）:**

| アプローチ | メリット | デメリット | 実現可能性 |
|------------|----------|------------|------------|
| アプリ内再生監視 (`NowPlayingInfoCenter`) | 正確な時刻取得 | Hearloomアプリ経由でしか記録できない（UX悪化） | ○ |
| 定期ポーリング+差分検出 | 実装が簡単 | 精度が低い、推定でしかない | △ |
| ユーザー入力補完 | 確実なデータ | 記録コストが発生（企画と矛盾） | △ |
| 時間帯要素をMVPから除外 | API制約回避 | 差別化ポイント弱体化 | ○ |

### 2. バックグラウンド同期が保証されない

**影響:**
- 「バックグラウンドで定期同期」（P0機能）の確実な実現が困難

**原因:**
- iOSのバックグラウンド実行制約
  - `BGAppRefreshTask`: システム判断で実行タイミングが決まる（15分間隔保証なし）
  - Silent Push Notification: 配信遅延（数分〜1時間）、Force Quit時は動作しない
  - 「Background App Refresh」設定がオフだと動作しない

**対策:**
- フォアグラウンド同期を優先
- ユーザーに定期的なアプリ起動を促すオンボーディング
- Silent Push + Background Fetchの併用（確実ではないが複数手段を組み合わせ）

### 3. その他の制約

- **最大50件の履歴制限**: Recent Playedは直近50曲まで（offset=0,10,20,30,40で5回取得）
- **スキップ検出不可**: APIでサポートされていない

## API制限

| 制限項目 | 内容 |
|----------|------|
| レートリミット | **20リクエスト/秒/ユーザー** |
| 1日あたりの上限 | 明示的な制限なし（ドキュメント上） |
| Recently Played取得上限 | **最大50件** |
| 1回あたりの取得上限 | 10件（limit指定しても10以上は効かない報告あり） |
| Developer Token有効期限 | **最大6ヶ月** |
| Music User Token有効期限 | **約6ヶ月** |

## 認証フロー

**複雑度:** 中〜高

**実装手順:**
1. Apple Developer Consoleで Media Identifier と Private Key を作成
2. サーバーサイドでJWT (Developer Token) を生成
3. アプリでユーザー認証をリクエスト
4. 取得したMusic User Tokenをキャッシュ
5. 6ヶ月ごとのトークン更新処理を実装

## App Store審査注意点

**App Review Guideline 4.5.2 への準拠が必要:**

1. **ユーザー主導の再生**: 再生はユーザーが開始し、標準的なメディアコントロールが使える必要あり
2. **課金制限**: Apple Musicへのアクセスに対して支払いを要求したり、間接的にマネタイズ（アプリ内課金、広告、ユーザー情報収集など）してはならない
3. **ファイルのダウンロード禁止**: MusicKit APIから取得した音楽ファイルのダウンロード・アップロード・共有は禁止
4. **ライセンスの確認**: 特定の楽曲を特定のタイミングで再生したい場合は、権利者から直接許諾が必要
5. **アートワーク使用制限**: カバーアートやメタデータは音楽再生やプレイリスト表示に限定、マーケティング・広告での使用は権利者の許諾が必要

## プライバシー配慮

- **Purpose String必須**: Apple Music user dataにアクセスする目的を明示
- **Privacy Policy必須**: App Store Connect と アプリ内の両方で明確なプライバシーポリシーへのリンクが必要
- **データ収集の開示**: どのデータを収集し、どう使用するかを明示

## 実現可能性の総合判定

| 機能 | 判定 | 理由 |
|------|------|------|
| Recently Played取得 | **○ 工夫が必要** | 基本機能は可能だが、タイムスタンプ欠如が致命的 |
| バックグラウンド定期同期 | **△ 制約あり** | iOSの制限により確実な定期実行は保証されない |
| 時間帯×ジャンル×頻度からAI推定 | **△ 制約あり** | 時間帯情報がAPIから取得できないため、代替アプローチが必要 |
| 曲・アーティスト・ジャンル情報取得 | **◎ 実現可能** | 十分なメタデータが取得可能 |
| スキップ検出 | **× 実現困難** | APIでサポートされていない |
