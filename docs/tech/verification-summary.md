## Spotify Web APIの詳細スペック

**取得可能な強力なデータ:**
- **タイムスタンプ**: ISO 8601形式、秒単位精度（例: `2024-01-15T14:30:00Z`）
- **Audio Features**: valence（明るさ）, energy（激しさ）, tempo, danceability等
- 曲名、アーティスト、アルバム、ジャンル、ジャケット画像
- 再生コンテキスト（プレイリスト名等）

**API制限:**
- Recently Played: 最大50曲まで
- レートリミット: 30秒ローリングウィンドウ（具体値非公開）
- Development Mode: **最大25ユーザー**（アローリスト登録必要）
- Extended Quota Mode: 組織のみ、**25万MAU以上必要**（2025年5月15日以降）

**Hearloomへの影響:**
- MVP段階: 25ユーザー制限内で運用
- スケール時: 法人化 + 25万MAU達成が必要（Catch-22問題）
- 対策案: Last.fm連携（Spotify scrobbling経由でユーザー数制限回避）

## 共有メニュー方式の詳細スペック

**実装方法:**
- iOS: Share Extension（App Extension）
- Android: Share Intent

**取得可能データ:**
- URL: すべての音楽アプリから取得可能
- 曲名・アーティスト: 共有テキストまたはoEmbed/API経由
- ジャケット画像: oEmbed/Open Graph/API経由（後から取得）
- タイムスタンプ: 共有操作時刻（実際の再生時刻との乖離あり）

**記録率シミュレーション（1日25曲聴取の場合）:**
| 時間帯 | シーン | 記録可能性 | 記録数予測 |
|--------|--------|------------|------------|
| 通勤（混雑） | 両手使えない | 低 | 0-1曲/5曲 |
| 昼休み | 食事中 | 中 | 1-2曲/3曲 |
| 作業中BGM | 集中妨げる | 中 | 2-3曲/7曲 |
| リラックス時 | 操作可能 | 高 | 3-4曲/5曲 |
| **合計** | | | **6-11曲/25曲（24-44%）** |

**採用理由:**
- API制約を完全回避
- すべての音楽サービスに対応可能
- 「特に印象的な曲」を記録する補助的手段として有用

## ShazamKit検証結果サマリー

**2024年1月のShazam新機能:**
Shazam v17.3で「iOSでもイヤホン使用時の音楽検出」が可能に。ただし：
- マイクへのアクセスが必要（内部オーディオではなく、音漏れ・骨伝導等を検出）
- バックグラウンドで約20秒後に停止（iOS 18制約）
- バッテリー消費: 1日14-50%
- 6時間で自動オフ

**Hearloomでの採用判定: 不可**
- iOS: サンドボックスにより他アプリのオーディオストリームへのアクセス不可
- イヤホン使用時（ターゲットユーザーの99%）は実質的に機能しない
- Apple所有アプリ（Shazam）でも、iOSでは内部オーディオ認識を実装していない
- サードパーティアプリでの再現は技術的に不可能

## 残された技術的課題

1. **Spotify Development Mode（25ユーザー制限）の突破**
   - 課題: 25ユーザー → 25万MAUの間にギャップ
   - 対策案: Last.fm連携、法人化 + 早期審査準備

2. **定期ポーリングの最適化**
   - 課題: 50曲制限内でデータ欠損を回避
   - 対策案: 数時間おきのポーリング、バックグラウンドフェッチの活用

3. **手動記録の記録率向上**
   - 課題: 24-44%は低すぎる
   - 対策案: UI/UX最適化、通知による記録促進、ウィジェット活用
